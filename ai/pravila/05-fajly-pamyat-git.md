## 3. Память (`ai/pamyat/`)

Память переехала из облачного проекта как есть: `MEMORY.md` — индекс одной строкой на запись, остальные файлы — по одной мысли.

**Формат файла памяти:**

```markdown
---
name: kratkoe-imya
description: одна строка — о чём запись, по ней решают, читать ли
metadata:
  type: user | feedback | project | reference
---

Факт или решение с абсолютной датой (2026-10-02).
**Why:** почему так решили.
**How to apply:** когда и как это применять. Связанные записи: [[drugaya-zapis]].
```

- `feedback` — как Никита хочет, чтобы ты работал (правила, поправки, похвала подходу). `project` — решения и итоги по игре. `user` — о Никите. `reference` — где что лежит.
- **Когда записывать:** Никита принял решение по механике или процессу; ввёл правило работы («запиши себе», «это общее требование»); поправил тебя; закончился тест или этап с итогом, который понадобится потом.
- **Перед записью** проверь, нет ли уже записи на эту тему: дополни её, а не плоди дубль. Неверную запись исправь или удали.
- Не записывай то, что уже лежит в файлах проекта: сошлись на файл. Файл памяти до ~4 КБ.
- После записи добавь или обнови строку в `ai/pamyat/MEMORY.md`.
- Правило работы, которое касается всех разговоров, дублируй строкой в нужный файл `ai/pravila/` (память — история и причины, `ai/pravila/` — действующие правила).

## 5. Git

- Коммить сам после законченной задачи: понятное сообщение на русском, что и зачем («Жрец: ответы на §9 отчёта 06, правки Возложения рук»). Не коммить половину работы.
- Пушь, когда Никита попросил, в `/itog` или когда план нужен серверу.
- Перед работой с планами и прогонами: `git pull`, сервер мог запушить результаты.
- В git не кладём: `syrye-dannye/`, `reports/progony/*/boi.jsonl`, `__pycache__`.
- Историю не переписывай (без `rebase -i`, `push --force`), чужие коммиты сервера не трогай.
