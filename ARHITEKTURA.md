# Архитектура проекта «Двое во тьме»

Что где лежит и зачем. Читают Никита и ИИ-помощники (Claude Code, Cursor). Структура введена 2026-10-04; старое расположение файлов можно посмотреть в коммите `e364fa4`.

## 1. Верхний уровень

```
design/       общие дизайн-документы игры
heroes/       герои: по папке на героя
dungeons/     подземелья: по папке на подземелье
playtest/     всё для тестов: методика, стенд (движок, бот, планы)
reports/      отчёты, журналы хода работ, логи и результаты прогонов
ai/           правила и память ИИ-помощника
ARHITEKTURA.md   этот файл
AGENTS.md, CLAUDE.md, .claude/, .cursor/   настройки ИИ-помощников; должны лежать в корне, иначе инструменты их не найдут
```

## 2. Папки

### `design/` — дизайн игры

Файлы `NN-imya.md`, номер задаёт порядок чтения.

| Файл | Что там |
|---|---|
| `01-prozharka-idei.md` | главный документ: идея, конкуренты, рынок, ядро боя, герои, забег, риски, коробка, выставка, итог |
| `02-videnie-i-principy.md` | видение и принципы игры |
| `03-bazovye-pravila.md` + `03-bazovye-pravila.yaml` | базовые правила; в YAML общие числа правил (рука, масло фонаря и т. д.), стенд читает их отсюда |
| `04-geroi-obshee.md` | общее устройство героев |
| `05-soglashenie-po-balansu.md` + `05-soglashenie-po-balansu.yaml` | соглашение по балансу (коридоры, пункты [С x.y]) и его машинная копия для стенда; меняется только с согласия Никиты |
| `06-podzemelye.md` | как устроено любое приключение: состав набора, раскладка пути, враги и колоды намерений, локации, события, отдых, механика приключения; по нему пишутся файлы в `dungeons/` (черновик) |

Новый документ получает следующий свободный номер.

### `heroes/<герой>/` — герои

```
heroes/mag/
  mag.md            дизайн-документ героя
  geroj.yaml        числа героя для стенда (здоровье и т. п.)
  karty/osnovnye/   карты колоды: стартовые и апгрейды, по YAML-файлу на карту
  karty/zapas/      запасные карты: в коробку не идут, но тестируются или протестированы и признаны хорошими
  karty/bank/        банк идей карт (YAML, nabor: bank; легендарки — legendarka): сырые идеи для тестов, числа черновые (Паладин и маг)
```

Герои: `mag`, `paladin` (бывший Жрец; внутри YAML у него пока прежний id `zhrec`), `luchnik`, `bard`.

**Где живут числа.** Числа карты живут в её YAML-файле: там текст, цена, числа, границы и история правок (`istoriya`). Стенд читает карты прямо отсюда и после подбора записывает новые числа сюда же. В дизайн-документе героя таблица карт с числами не пишется руками: её собирает `python run.py tablica` (из `playtest/stend/`) в раздел «Карты (числа из YAML)» между метками `karty:nachalo` и `karty:konec`. Запускать после любой правки карт; стенд после подбора чисел таблицу сам не обновляет.

Перенос карты между колодой и запасом: перенести файл из `osnovnye/` в `zapas/` (или обратно) и поменять в нём `nabor` (`apgrejd` ↔ `zapas`).

### `dungeons/<подземелье>/` — подземелья

```
dungeons/katakomby/
  katakomby.md      дизайн-документ подземелья
  vragi/            враги, по YAML-файлу на врага
  lokacii/          комнаты, по YAML-файлу на комнату
```

### `playtest/` — тесты

| Путь | Что там |
|---|---|
| `metodika-testa-bilda.md` | методика теста билда |
| `stend/` | стенд: `engine/` (правила боя), `stend/` (бот, ситуации, метрики, запуск планов), `plans/` (планы тестов), `etalon/` (эталонные карты для сравнения силы), `run.py` (единственная команда запуска) |
| `stend/AGENTS.md`, `stend/.cursor/`, `stend/.claude/` | правила агента-исполнителя на сервере |

Стенд собирает игру из `design/*.yaml`, `heroes/` и `dungeons/`, а результаты прогонов пишет в `reports/progony/`.

### `reports/` — отчёты

| Путь | Что там |
|---|---|
| `mag/`, `paladin/` | отчёты, планы и ход тестов, концепты после тестов; старые симуляторы в `test*/sim` |
| `obshchie/` | первые прогоны маг + Жрец, обычный тест №1, замеры времени, итог сборки стенда |
| `progony/<план>/` | результаты планов стенда: `itog.md`, отчёты фаз, `zhurnal.md`, `progress.md` |

Новый отчёт кладётся в папку героя (или в `obshchie/`) со следующим номером: `reports/mag/23-tema.md`. Старые отчёты не переписываются: их можно переносить между машинами как есть. Сырьё прогонов (`boi.jsonl`) в git не идёт.

### `ai/` — помощник

| Путь | Что там |
|---|---|
| `pravila/` | правила работы ИИ по темам: общение, дизайн, баланс и тесты, стенд и сервер, файлы и git, уроки |
| `pamyat/` | память проекта: решения Никиты, правила, итоги; `MEMORY.md` — индекс |

Это правила для ИИ-помощника в разговоре с Никитой, а не логика ботов: как боты думают в бою, задаёт код `playtest/stend/stend/bot.py`.

## 3. Как работать каждый день

| Что хочешь | Как |
|---|---|
| Начать | `/nachalo` (можно с темой: `/nachalo маг`) |
| Прожарить идею, механику, документ | `/prozharka <что>` |
| Пройти открытые вопросы | `/voprosy <тема>`, отвечаешь «1а 2б» |
| Записать решение или правило | «запомни …» или `/zapomni` |
| Карты героя | `/karty <герой, билд, что нужно>` |
| Дизайн-документ | `/dizajn-dok <тема>` |
| Быстро проверить идею на стенде | `/korotkij-test` + твоё слово на запуск |
| Длинный тест на сервере | `/plan-testa` → push → сервер `/progon-plana` → `/razbor-progona` |
| Ответ не понравился, ошибка | скажи прямо; `/urok` закрепит правило |
| Чат стал длинным | `/svodka` → новый чат → вставить сводку |
| Закончить | `/itog` (обновит память, сделает коммит) |

Субагенты (`.claude/agents/`): `kritik` — слабые места; `nastolshchik` — другие игры и рынок; `balansirovshchik` — баланс и стенд; `igrok-novichok` — взгляд новичка на карты и правила. Кто когда нужен — `AGENTS.md` §6.

## 4. Стенд локально и на сервере

Нужны Git и Python 3.10+ (на Linux `python3` вместо `python`).

```
cd playtest/stend
pip install -r requirements.txt
python run.py proverka                     # данные игры и тесты движка
python run.py tablica                      # обновить таблицы карт в документах героев
python run.py plans/<план>.yaml --minut 9  # план кусками по 9 минут (код 3 — пауза, запусти снова)
```

**Сервер.** Склонировать весь репозиторий (стенду нужны `design/`, `heroes/`, `dungeons/`), в Cursor открыть папку `playtest/stend/`: тогда агент видит только свои правила (`AGENTS.md`, `.cursor/rules/stend.mdc`, скилл `/progon-plana`). Модель для исполнителя подешевле (Sonnet или Composer). Задача агенту:

```
/progon-plana plans/<файл плана>.yaml
```

или словами:

```
git pull. Прочитай AGENTS.md. Запусти план plans/<файл>.yaml по правилам из AGENTS.md:
сначала python run.py proverka, потом кусками python run.py plans/<файл>.yaml --git --minut 9:
код 3 — пауза, проверь ../../reports/progony/<имя>/progress.md и запусти ту же команду снова; код 0 — план выполнен.
При зависании или падении перезапускай той же командой.
После каждой фазы: git pull --rebase и git push. Не заканчивай раньше срока. В конце запушь всё и напиши итог в zhurnal.md.
```

Если агент бросает работу посреди плана, запусти команду сам в отдельном терминале без `--minut`: она идёт до конца и коммитит после каждой фазы.

## 5. Настройка ИИ-помощников

- **Claude Code:** в корне репозитория `claude`, `/model` → Opus, высокий уровень рассуждения, затем `/nachalo`. Правила подхватываются из `CLAUDE.md` → `AGENTS.md`.
- **Cursor:** открыть корень репозитория, модель Claude Opus с высоким уровнем рассуждения (не Auto), режим Agent. Правила — `AGENTS.md` и `.cursor/rules/`. Автоматической памяти Cursor не доверять: память проекта в `ai/pamyat/`.
- Если ответы стали хуже: проверить модель, начать новый чат через `/svodka`, напомнить «отвечай по AGENTS.md §3».
