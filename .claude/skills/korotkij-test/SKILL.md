# Короткий тест на стенде

Тест запускается **только по слову Никиты**. Если он не назвал срок — не дольше 15–20 минут; дольше часа — это задача для сервера (`/plan-testa`).

Тест можно поручить субагенту `balansirovshchik`: передай ему гипотезу, что менять, срок и слово Никиты дословно. В Claude Code его можно запустить в фоне и продолжать разговор; его отчёт перескажи по формату «Итог» ниже.

## Подготовка

1. Прочитай `pravila/03-balans-i-testy.md` и `pravila/04-stend-i-server.md`.
2. В `stend/`: `python run.py proverka` (на Linux `python3`).
3. Сформулируй гипотезу одной фразой и скажи Никите: что проверяю, сколько минут, какое число будет ответом.
4. Напиши мини-план `stend/plans/lok-ГГГГ-ММ-ДД-imya.yaml` (префикс `lok-` — локальные). Временные правки чисел — через `pravki` в плане, файлы карт не трогай, пока не решишь, что правка остаётся.

## Запуск и присмотр

- Запуск кусками по 9 минут (без `--git`): `python run.py plans/lok-….yaml --minut 9`. Код 3 — пауза, всё сохранено: прочитай `stend/runs/<имя>/progress.md`, одной строкой скажи Никите, что видно, и запусти ту же команду. Код 0 — план выполнен. Так присмотр раз в 10 минут получается сам собой и в Claude Code, и в Cursor.
- За кусок не прибавилось боёв или другой код выхода — смотри `zhurnal.md`, странный бой разбери командой `python run.py boj …`, почини и запусти снова.
- Нужна длинная серия из нескольких шагов — по каждому шагу короткий отчёт (что сделал, главное число, что дальше).

## Итог

Сразу по завершении, не жди вопроса:
- ответ на гипотезу первой строкой («Подтвердилось: …» / «Нет: …»);
- таблица раунды / потери против коридоров (база и вариант);
- шум: сколько боёв, насколько можно верить разнице;
- «Решил сам»: какие числа оставил (тогда перенеси их в YAML карты с записью в `istoriya`);
- вопросы по механике, если появились.

`stend/runs/lok-*` в git не коммить, если Никита не попросил (это черновые прогоны); выводы — в файл темы.
