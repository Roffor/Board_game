# Стенд, сервер и обмен через git

## 1. Схема работы (решение Никиты 01.10)

1. **Дизайн-документ** вместе с Никитой: концепт, мотивация, решения, минимум воды (`/dizajn-dok`).
2. **План теста, ограниченный временем**, тоже вместе (`/plan-testa`). Гипотезы записаны до запуска.
3. **Прогон на сервере Никиты** агентом Cursor попроще (облачная модель из подписки Cursor). Агент запускает, следит, перезапускает, правит числа в границах плана, пушит результаты.
4. **Анализ вместе** (`/razbor-progona`).

Короткие проверки (до часа) пока делаем сами во время обсуждения (`/korotkij-test`). Цель — перейти только на длинные тесты на сервере.

**Сервер:** AMD Ryzen 9 9950X3D (16 ядер / 32 потока), RTX 5080. Видеокарта стенду не нужна: бот считается на процессоре. В облаке на 4 ядрах было 2,3 боя/с; на сервере ожидалось 12–15 боёв/с, около 50 тысяч боёв в час (прикидка, не замер: первый прогон на сервере её проверит).

## 2. Устройство стенда (`stend/`)

| Часть | Что это | Кто меняет |
|---|---|---|
| `game/` | игра как данные: файл YAML на карту (`geroi/<герой>/karty/`, `bank/`, `etalon/`), враги, комнаты, `pravila.yaml`, `soglashenie.yaml` | числа — агент в границах плана и ты; механики карт — мы с Никитой |
| `engine/` | правила боя: словарь эффектов (`effects.py`), особые механики (`special.py`, обработчики `osobyj`), бой (`fight.py`). О тестах не знает | только мы, с проверкой |
| `stend/` | бот, колоды и ситуации [С 8.7], метрики, подбор чисел, запуск по плану, отчёты | только мы |
| `plans/` | планы тестов | пишем мы с Никитой |
| `runs/<план>/` | результаты: `progress.md`, `zhurnal.md`, `otchet-<фаза>.md`, `itog.md`, `meta.json`; `boi.jsonl` (сырьё и чекпоинт, в git не идёт) | пишет команда запуска |

Подробное устройство и формат карты: `stend/README.md`, `process/02-stend-specifikaciya.md`, итог сборки и сверка со старым симулятором: `process/03-stend-gotov.md`. Правила агента-исполнителя: `stend/AGENTS.md` (там же формат плана).

**Команды** (из папки `stend/`; на Linux `python3` вместо `python`):

```
pip install -r requirements.txt
python run.py proverka                       # данные игры и тесты движка (карты во всех вариантах + золотые бои)
python run.py plans/<план>.yaml              # запуск или продолжение с чекпоинта
python run.py plans/<план>.yaml --git        # то же, коммит после каждой фазы
python run.py plans/<план>.yaml --minut 9    # кусками: через 9 минут пауза (код 3), та же команда продолжит; код 0 — готово
python run.py boj <I|II|EL|BOSS> <номер> [сид] # один бой с подробным журналом
# ключи: --yader N, --bez-dyma
```

Типы фаз: `progon` (варианты против коридоров), `test_bilda` (сила карт против эталонов, следующие волны только неясным картам), `podbor` (`cel: sila` — сила карты к центру нормы; `cel: koridory` — средние раунды и потери к центрам коридоров).

## 3. Как менять стенд

- **Новая карта или правка механики карты:** файл в `game/geroi/<герой>/karty/` (или `bank/`), текст собирается из `chisla`, эффект из словаря `engine/effects.py`. Если словаря не хватает — именованный обработчик в `engine/special.py`. У карты задай `granicy` (в каких пределах агент может двигать числа), `zamenyaet` (какую стартовую заменяет), подсказку боту `bot`.
- **Правка правил боя в `engine/`:** после неё `python run.py proverka`. Если золотые бои изменились и так задумано — перезапиши эталон осознанно, подними `RULES_VERSION` в `engine/__init__.py`, запиши в журнал.
- **Правка бота или стенда:** проверь, что дымовой план (`plans/primer-dym.yaml`) проходит, и сравни базу до и после на одних сидах.
- Каждое изменение числа — запись в `istoriya` карты (дата, кто, было → стало, почему).

## 4. Как писать план для сервера

Агент на сервере слабее тебя и не умеет принимать дизайнерские решения. Поэтому:
- **Любое «если» — условие на число.** Не «посмотри и реши», а «если средние раунды босса > 6, двигай `karta.X.uron` на −1 в границах [2, 4]».
- План — либо **сетка вариантов**, заданная заранее (вариант 0, правки A, B, C, смелые идеи 1–3) в порядке приоритета, либо **числовой подбор по правилу** (фаза `podbor`). Не «итерируй, пока не сойдётся».
- **Время, а не бои:** `srok_chasov` и `dolya` у фаз. Команда сама меряет скорость и делит часы; недобранное время отдаёт следующим фазам.
- **Гипотезы** и критерии успеха записывай в md рядом с планом (`plans/<план>.md`): что ожидаем, что будем считать подтверждением.
- **Дотесты** на случай, если фазы закончатся раньше: явный список вариантов в конце плана.
- **Перед отдачей на сервер** прогони план локально коротко (уменьши `srok_chasov` до 0,05 в копии плана) и убедись, что фазы проходят без ошибок. Ошибка в плане не должна стоить ночи.
- Права агента в плане: что можно менять (`parametry` фазы подбора, явный список), в каких границах, можно ли переносить карты между колодой и банком.
- Механики ночью не меняются. Только если Никита прямо разрешил в плане.

## 5. Git-обмен

Один репозиторий на всё: дизайн и стенд вместе. На сервере Никита открывает в Cursor папку `stend/`, на своей машине — корень репозитория.

- Мы: пишем план в `stend/plans/`, коммитим, пушим. Никита на сервере делает `git pull` и даёт агенту задачу (готовый текст — в `README.md`, раздел про сервер).
- Агент: `python run.py plans/<план>.yaml --git` коммитит после каждой фазы; перед пушем `git pull --rebase`, потом `git push`.
- Мы: `git pull`, читаем `stend/runs/<план>/itog.md` и отчёты фаз.
- `boi.jsonl` в git не идёт: около 1,3 КБ на бой, на сервере это ~60 МБ в час, а GitHub не принимает файлы больше 100 МБ. Сырьё остаётся на сервере. Если для разбора нужны сырые бои, попроси Никиту выгрузить выборку или запустить `python run.py boj …` для показательных боёв.

## 6. Открытые вопросы по стенду (ждут Никиту с 01.10)

1. «1 урон» против Брони 1: правило «Броня не опускает попадание ниже 1» (рекомендация: совпадает со старыми тестами, ярус II 3,04 раунда) или оставить как напечатано и перенастроить ярус II (сейчас 3,56 при коридоре 3–3,5).
2. Кровь на алтаре: одно Подношение (как тестировали) или «сколько угодно» (как в `cards/mag/22`).
3. Сглаз: 1 Порча (как тестировали) или 2 (как в документе).
4. Первый реальный прогон на сервере: замерить скорость, обновить прикидку в этом файле.
