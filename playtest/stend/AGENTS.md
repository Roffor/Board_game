# Правила для агента

Ты гоняешь длинные тесты баланса настольной игры «Двое во тьме» (кооперативный колодостроительный рогалик на двоих: Маг и Паладин, в данных у него id `zhrec`) по плану из `plans/`. Дизайн и выводы делают люди; твоя работа — запустить план, следить за ним, чинить запуск и править числа игры в границах плана.

## Что где лежит

| Папка | Что это | Тебе можно |
|---|---|---|
| `../../heroes/<герой>/karty/` | карты героев (YAML): `osnovnye/` — колода, `zapas/` — запас | менять **числа** в границах плана; переносить карты между `osnovnye/` и `zapas/` |
| `../../dungeons/<подземелье>/` | враги (`vragi/`) и комнаты (`lokacii/`), YAML | менять **числа** в границах плана |
| `../../design/03-bazovye-pravila.yaml` | общие числа правил | менять **числа** в границах плана |
| `../../design/05-soglashenie-po-balansu.yaml` | пороги соглашения по балансу | только читать |
| `etalon/` | эталоны силы карт | только читать |
| `engine/` | движок: правила игры как код | не трогать |
| `stend/` | бот, запуск, подбор, отчёты | не трогать |
| `plans/` | планы тестов | не трогать (пишут люди) |
| `../../reports/progony/` | результаты прогонов | пишет команда запуска; ты коммитишь и пушишь |

Если для задачи нужно поменять `engine/`, `stend/`, `plans/` или соглашение — остановись и опиши в `../../reports/progony/<прогон>/zhurnal.md`, что нужно и почему, закоммить и запушь.

## Как запускать

```
python run.py proverka                      # данные игры и тесты движка; запускай перед каждым планом
python run.py plans/<план>.yaml --git       # план целиком; перезапуск той же командой продолжит с места остановки
python run.py plans/<план>.yaml --git --minut 9   # то же кусками по 9 минут: код 3 — пауза, запускай снова; код 0 — план выполнен
python run.py boj <I|II|EL|BOSS> <номер> [сид]   # один бой с подробным журналом, для разбора странностей
```

Нужны Python 3.10+ и `pyyaml`. Команда сама берёт все ядра, делит срок плана по фазам, пишет чекпоинты, отчёты и (с `--git`) коммитит после каждой фазы. Пушить — тебе: после каждой фазы и в конце.

## Git

- Стенд лежит в папке `playtest/stend/` общего репозитория проекта. Открывай в Cursor именно папку `playtest/stend/` и запускай все команды из неё. Данные игры лежат вне этой папки (`../../heroes/`, `../../dungeons/`, `../../design/*.yaml`): в них меняй только числа, как сказано выше. Документы `.md` в остальных папках не трогай.
- Перед запуском плана: `git pull`.
- После каждой фазы и в конце: `git pull --rebase`, затем `git push`. Если `pull --rebase` дал конфликт — не решай его силой: `git rebase --abort`, опиши в `zhurnal.md` и сообщи человеку.
- `../../reports/progony/*/boi.jsonl` в git не идёт (он в `.gitignore`): это сырьё и чекпоинт, около 1,3 КБ на бой, за ночь сотни мегабайт, а GitHub не принимает файлы больше 100 МБ. Файл остаётся на сервере, не удаляй его до конца плана.
- Никогда не делай `git push --force`, `git reset --hard` и не переписывай историю.

## Пока план идёт

- **Удобнее всего запускать кусками:** `python run.py plans/<план>.yaml --git --minut 9`. Команда сама остановится через 9 минут с кодом 3, сохранив всё; ты смотришь `progress.md` и `zhurnal.md`, пушишь, если закончилась фаза, и запускаешь ту же команду снова. Так присмотр раз в 10 минут получается сам собой и не нужен фоновый процесс. Код 0 — план выполнен.
- Раз в 10 минут смотри `../../reports/progony/<прогон>/progress.md`. Если он не обновлялся больше 10 минут — процесс завис: останови его и запусти ту же команду снова (продолжит с чекпоинта). Запиши это в `zhurnal.md`.
- Если процесс упал — перезапусти той же командой. Если падает снова на том же месте — не обходи ошибку, опиши её в журнале и запушь.
- Ошибки отдельных боёв (поле `error` в `boi.jsonl`) — это баг движка или данных. Больше 1% ошибок в фазе — остановись и опиши.
- Срок плана — это объём работы, а не предел. Не заканчивай раньше; если фаза кончилась быстрее, команда сама отдаёт время следующим.

## Правки чисел

- Менять можно только то, что разрешает план (раздел `parametry` фазы подбора или явный список в плане), и только внутри указанных границ. У каждой карты есть свои `granicy` — за них выходить нельзя, движок не загрузит такую карту.
- Каждая правка карты записывается в её `istoriya`: дата, кто, было → стало, почему. Подбор делает это сам; при ручной правке — пиши сам.
- Механику (поля `effekt`, `varianty`, `osobyj`, тексты, `vid`, свойства врагов) не меняй, если план прямо не разрешил.
- **Исключение — банк идей** (карты с `nabor: bank` в `../../heroes/<герой>/karty/bank/`, решение Никиты 2026-10-25): если план разрешает правку банка, ты можешь добавлять картам урон и щит, менять любые числа, расширять `granicy` и немного менять концепт (порог условия, маленький базовый эффект, «вдвое» → «ещё N», упрощение отслеживания). Ресурс, статус и механику героя, на которых держится идея, не меняй (у Паладина — вера, Заслон, Молитва, благословения; у мага — мана, сжигание, Подношение, Порча, долг духам; правила мага для банка — `engine/mag2.py`). Каждая правка — в `istoriya` карты и отдельной строкой в `zhurnal.md` с пометкой «концепт», если менялся не только счёт.
- Здоровье рядового врага не больше 20, элиты не больше 40 [С 4.1]. Силу карт не компенсируй здоровьем врагов — ослабляй карты.
- Замена карт: можно перенести файл карты из `../../heroes/<герой>/karty/osnovnye/` в `karty/zapas/` и обратно, поменяв `nabor` (`apgrejd` ↔ `zapas`). Запиши это в журнал.

## Отчёты

После каждой фазы — `../../reports/progony/<прогон>/otchet-<фаза>.md`, в конце — `itog.md`. Не переписывай их руками. Если хочешь что-то добавить (наблюдение, странный бой) — пиши в `zhurnal.md` отдельной строкой с датой.

## Формат плана (кратко)

```yaml
nazvanie: имя-прогона
srok_chasov: 6
seed0: sluchajno            # или число
geroi: {mag: {apgrejdy: sluchajno, pul: apgrejd}, zhrec: {apgrejdy: sluchajno, pul: apgrejd}}   # pul: apgrejd | bank | apgrejd+bank | [id, ...]; легендарки — в obyazatelno
pravki: {}                  # временные правки на весь план: {karta.<id>.<число>: N, vrag.<id>.zdorove: N, pravila.<ключ>: N}
fazy:
- {id: baza, tip: progon, dolya: 0.2, varianty: [{metka: baza}]}
- {id: bild, tip: test_bilda, dolya: 0.5, geroj: mag, karty: [rok, gnil]}     # или bild: П (для банка: bild: З, nabory: [bank])
- {id: podbor, tip: podbor, dolya: 0.3, cel: sila, zapisyvat: true,
   parametry: [{chislo: karta.rok.mnozhitel, shag: 1, granicy: [3, 5]}]}
```

Типы фаз: `progon` — варианты против коридоров соглашения; `test_bilda` — сила каждой карты против эталонов [С 8.8–8.9], следующие волны — только картам с неясным итогом; `podbor` — перебор чисел (`cel: sila` — сила карты к центру нормы, `cel: koridory` — средние раунды и потери к центрам коридоров).
