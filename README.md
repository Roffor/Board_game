# Настолка «Двое во тьме»: работа на своей машине

Здесь весь проект из облачного проекта Claude на 2026-10-02 и всё, чтобы продолжить разговор с ИИ на своей машине так же, как в облаке: правила общения, память проекта, команды и правила для Cursor и Claude Code, стенд для сервера.

## Коротко

1. Распакуй архив, сделай из папки git-репозиторий и запушь в приватный GitHub (§3).
2. Для разговоров о дизайне **рекомендую Claude Code** на модели Opus (§4): он ближе всего к облачному проекту и тратит лимиты подписки Claude, а не Cursor. Cursor с теми же правилами тоже подойдёт (§5).
3. На сервере открой в Cursor папку `stend/` и дай агенту задачу (§6). Для агента на сервере хватит дешёвой модели.
4. В начале разговора набирай `/nachalo`, в конце `/itog`.

## 1. Честно о качестве общения

Качество зависит прежде всего от **модели**, потом от **обёртки** инструмента, и только потом от инструкций. В Copilot было хуже не из-за инструкций проекта, а по трём причинам:

1. **Модель.** Режим «Auto» и низкий уровень рассуждения дают более слабые и поверхностные ответы. Модель надо выбирать явно.
2. **Системная инструкция инструмента.** Copilot и Cursor сделаны под правку кода и просят модель отвечать максимально кратко. Отсюда обрывки вместо объяснений.
3. **Контекст.** Длинный чат сжимается, договорённости теряются, памяти проекта нет.

Что с этим делает комплект:
- правила общения (`AGENTS.md` §3, подробно `pravila/01-obshchenie.md`) прямо говорят модели, что они главнее установки на краткость. Их подхватывают и Cursor, и Claude Code;
- память проекта (`pamyat/`), состояние работ (`STATUS.md`) и команда `/nachalo` возвращают контекст в каждый новый чат;
- `/svodka` переносит договорённости в новый чат, когда старый стал длинным.

Модель выбираешь ты (§4, §5). С той же моделью (Claude Opus 5.5) и этими правилами общение должно быть близким к облачному. Полностью таким же оно не будет, и вот чего локально нет:
- **тредов и параллельной работы.** Один чат — одна тема. Параллельно можно держать несколько окон или вкладок;
- **будильника.** В облаке я сам просыпался раз в 10 минут, чтобы проверить прогон. Локальный агент сам себя не разбудит, поэтому стенд теперь умеет работать кусками (`--minut 9`): команда сама встаёт на паузу через 9 минут, агент смотрит прогресс и запускает дальше. Так короткие тесты удобно гонять и в Claude Code, и в Cursor, пока чат открыт. Всё длиннее часа — на сервер, там тем же способом следит агент-исполнитель;
- **работы с телефона.** Облачный проект доступен из приложения. У Claude Code есть Remote Control: локальную сессию можно продолжать с телефона, пока компьютер включён (настройка в документации Claude Code).

## 3. Репозиторий

Нужны [Git](https://git-scm.com/) и Python 3.10+ (на Windows ставь Git for Windows, команда Python — `python`; на Linux и macOS — `python3`).

1. Распакуй архив, перейди в папку `nastolka`.
2. Создай на GitHub **приватный** репозиторий без README, например `nastolka`.
3. В папке проекта:
   ```
   git init -b main
   git add .
   git commit -m "Перенос проекта из облачного Claude"
   git remote add origin https://github.com/<твой-логин>/nastolka.git
   git push -u origin main
   ```
4. Проверь стенд:
   ```
   cd stend
   pip install -r requirements.txt
   python run.py proverka
   ```
   Должно закончиться без ошибок (проверка карт во всех вариантах и золотых боёв).

## 4. Claude Code (рекомендую для дизайна)

Почему он: это тот же агент, что работал в облачном проекте, без установки на краткость кода; длинные команды держит в фоне; тратит лимиты подписки Claude, а бюджет Cursor остаётся на сервер, как ты и хотел.

1. Установи. macOS / Linux: `curl -fsSL https://claude.ai/install.sh | bash`. Windows (PowerShell): `irm https://claude.ai/install.ps1 | iex`. Если не сработает — актуальная инструкция на [code.claude.com](https://code.claude.com/docs).
2. В папке проекта запусти `claude`, войди своим аккаунтом Claude (нужна подписка Pro или Max).
3. Набери `/model` и выбери **Opus**. Если инструмент предлагает уровень рассуждения (effort, thinking), ставь высокий.
4. Набери `/nachalo`. Агент прочитает `STATUS.md` и память и скажет, где мы остановились.
5. Проверка, что правила подхватились: спроси «какие правила проекта ты видишь и как ты должен со мной общаться?». В ответе должны быть `AGENTS.md` и правила из §3.

Удобный вариант: расширение **Claude Code** для VS Code ставится и в Cursor. Тогда в одном окне и редактор Cursor, и чат Claude Code на подписке Claude.

Режимы: для чистого обсуждения без правок файлов можно включить plan mode (Shift+Tab), но правила и так запрещают править файлы в ответ на вопрос.

## 5. Cursor

1. Обнови Cursor до свежей версии (нужны скиллы и вложенные `AGENTS.md`).
2. File → Open Folder → папка `nastolka`.
3. **Модель:** в списке моделей чата выбери **Claude Opus 5.5** с высоким уровнем рассуждения (thinking high). **Не Auto.** Если есть Max Mode — включай для длинных разговоров (больше контекста). Учти: это расходует бюджет Cursor.
4. Режим: **Agent** для работы, **Ask** для разговора без правок.
5. Проверка: Cursor Settings → Rules — в списке `AGENTS.md` и правила из `.cursor/rules` (`00-osnova` всегда, остальные по папкам). В чате набери `/` — должны появиться `nachalo`, `voprosy`, `karty` и остальные. Затем `/nachalo`.
6. Необязательно, но полезно: Cursor Settings → Rules → **User Rules** (для всех проектов):
   ```
   Отвечай по-русски, на «ты». Ответ в первой фразе, дальше связный текст с причинами, без воды и итоговых пересказов.
   Высказывай своё мнение и спорь с аргументом; проверенное отделяй от предположений. Не урезай объяснение ради краткости.
   ```
7. Если в Cursor включены автоматические Memories, не полагайся на них: память проекта — в `pamyat/`, общая для обоих инструментов.

## 6. Сервер (агент-исполнитель)

1. Установи Git, Python 3.10+, Cursor. Клонируй репозиторий: `git clone https://github.com/<твой-логин>/nastolka.git`.
2. `cd nastolka/stend`, `pip install -r requirements.txt`, `python run.py proverka`.
3. Первый запуск — дымовой план на 10 минут, он же замерит скорость: `python run.py plans/primer-dym.yaml`. Скорость (боёв в секунду) пришли в разговор: от неё зависят объёмы планов.
4. В Cursor открой **папку `nastolka/stend`** (не весь репозиторий): тогда агент видит только свои правила (`stend/AGENTS.md`, `stend/.cursor/rules/stend.mdc`, скилл `/progon-plana`).
5. Модель для исполнителя — подешевле: Sonnet 5.5 или Composer. Ему не нужно думать о дизайне, только запускать, следить и чинить запуск.
6. Задача агенту (готовый текст, его же выдаёт `/plan-testa`):
   ```
   /progon-plana plans/<файл плана>.yaml
   ```
   или словами:
   ```
   git pull. Прочитай AGENTS.md. Запусти план plans/<файл>.yaml по правилам из AGENTS.md:
   сначала python run.py proverka, потом кусками python run.py plans/<файл>.yaml --git --minut 9:
   код 3 — пауза, проверь runs/<имя>/progress.md и запусти ту же команду снова; код 0 — план выполнен.
   При зависании или падении перезапускай той же командой.
   После каждой фазы: git pull --rebase и git push. Не заканчивай раньше срока. В конце запушь всё и напиши итог в zhurnal.md.
   ```
7. Если агент Cursor всё равно бросает работу посреди плана (заканчивает ход), запусти команду сам в отдельном терминале без `--minut` — она идёт до конца и сама коммитит после каждой фазы, а агента попроси только проверять прогресс и пушить.

`runs/*/boi.jsonl` (сырьё каждого боя) в git не идёт: за ночь там сотни мегабайт, а GitHub не принимает файлы больше 100 МБ. Он остаётся на сервере.

## 7. Как работать каждый день

| Что хочешь | Как |
|---|---|
| Начать | `/nachalo` (можно с темой: `/nachalo жрец`) |
| Обсудить идею | просто пиши: у каждой идеи, твоей и моей, будут сильное и слабое |
| Прожарить идею, механику, документ или моё решение | `/prozharka <что>`; без аргумента — последнее предложенное в чате |
| Пройти открытые вопросы | `/voprosy <тема>` — группы до 5, отвечаешь «1а 2б» |
| Записать решение или правило | «запомни …» или `/zapomni` |
| Карты героя | `/karty <герой, билд, что нужно>` |
| Дизайн-документ | `/dizajn-dok <тема>` |
| Проверить документ, карты или план чужими глазами | «отдай критику» (субагент `kritik`) |
| Как это сделано в других играх, насколько мы уникальны | «спроси настольщика» (субагент `nastolshchik`) |
| Баланс: тест, разбор прогона, числа | «поручи балансировщику» (субагент `balansirovshchik`), тест — с твоим словом на запуск |
| Понятны ли карты и правила новичку | «дай игроку-новичку» (субагент `igrok-novichok`) |
| Быстро проверить идею на стенде | `/korotkij-test` + твоё слово на запуск |
| Длинный тест на сервере | `/plan-testa` → push → сервер `/progon-plana` → `/razbor-progona` |
| Ответ не понравился, ошибка | скажи прямо; `/urok` закрепит правило |
| Чат стал длинным | `/svodka` → новый чат → вставить сводку |
| Закончить | `/itog` (обновит STATUS, память, сделает коммит) |

Один чат — одна тема. Новая тема — новый чат с `/nachalo`.

**Субагенты** — помощники со своей ролью, которых основной агент запускает в отдельном чистом контексте. Они не видят ваш разговор, поэтому смотрят свежим взглядом; основной агент ставит им задачу и пересказывает тебе их выводы со своим мнением. Описания лежат в `.claude/agents/`, их видят и Claude Code, и Cursor.

| Субагент | Что делает | Права |
|---|---|---|
| `kritik` — критик | ищет слабые места идеи и нарушения решений проекта; проверяет документы, карты и планы перед показом тебе | только читает |
| `nastolshchik` — настольщик | ищет, как похожее решено в других настолках, оценивает уникальность и качество проекта, смотрит глазами издателя; факты проверяет поиском со ссылками | только читает и ищет в интернете |
| `balansirovshchik` — балансировщик | короткие тесты на стенде, разбор прогонов, числа карт и врагов в пределах соглашения, планы для сервера | читает, правит числа, запускает стенд — тест только по твоему слову |
| `igrok-novichok` — игрок-новичок | читает тексты карт и правила глазами человека на выставке: понятно ли за 10 секунд, что спросят, что забудут, чем занят второй; в конце список, что проверить в живой партии | только читает |

Звать можно словами («прожарь через критика и настольщика»), основной агент зовёт их и сам: в полной прожарке, перед показом крупного документа, в задачах баланса. В Claude Code список субагентов — команда `/agents`. Все четыре работают на той же модели, что и основной чат (`model: inherit`): им нужна сильная модель. Если хочешь сэкономить лимиты, балансировщику в Claude Code можно поставить `model: sonnet` в его файле, но разбор прогонов на Opus точнее. В Cursor вместо `sonnet` нужно писать точное имя модели из его списка.

## 8. Если ответы стали хуже

1. Проверь модель: не Auto, Opus, высокий уровень рассуждения.
2. Чат слишком длинный: `/svodka`, новый чат, `/nachalo`.
3. Напомни: «отвечай по AGENTS.md §3». Если нарушение повторяется — `/urok`, чтобы правило попало в `pravila/uroki.md` и стало заметнее.
4. Спроси, какие правила агент видит. Если не видит `AGENTS.md` — открыта не та папка (нужна корневая `nastolka`) или Cursor старый.
5. Правила — обычные файлы, их можно править руками. Главное место — `AGENTS.md` §3.
